## 💡 Overview

Speculative decoding verifies drafted tokens sequentially and discards every
position from the first rejection onward, yet draft models are usually trained
with token-level imitation and a fixed per-position weighting. **VAT** simulates
verification at every training step and turns the resulting accept/reject
pattern into supervision:

- **Verification head**: a single linear layer on the draft's last hidden
  states, trained jointly with the draft (binary cross-entropy) to predict
  whether each position survives sequential verification.
- **Verification-adaptive weighting**: positions up to and including each
  sample's first rejection `k*` keep full weight, and the base decay schedule is
  re-anchored to start at `k*`.

The per-position objective combines soft-label (target distribution) and
hard-label cross-entropy under these weights, plus the verification-head loss.
VAT modifies only the training objective; the draft architecture, the target
model, and the inference procedure are unchanged.

This repository implements VAT for [DFlash](https://github.com/z-lab/dflash)
draft training on top of [SpecForge](https://github.com/sgl-project/SpecForge).
A VAT-trained draft is a standard `DFlashDraftModel`.

## 🛠️ Installation

```bash
$ git clone https://github.com/naver-ai/VAT.git
$ cd VAT

$ uv venv -p 3.12 --seed
$ source .venv/bin/activate
$ uv pip install -v -e . --prerelease=allow
```

This installs the pinned `torch==2.11.0`, `transformers==5.8.1`, and
`sglang==0.5.14`. Training runs the target model inside the trainer, so no
SGLang server or Mooncake is needed.

## 🗂️ Dataset Preparation

The training set pairs [Perfectblend](https://huggingface.co/datasets/mlabonne/open-perfectblend) user prompts with
responses generated by the target model using greedy decoding.

1. Download Perfectblend; this writes `./cache/dataset/perfectblend_train.jsonl`:

   ```bash
   python scripts/prepare_data.py --dataset perfectblend
   ```

2. Regenerate the responses with the target model. Start an SGLang server, then
   run the regeneration script with temperature 0 and thinking disabled:

   ```bash
   python -m sglang.launch_server \
       --model-path Qwen/Qwen3-4B \
       --dtype bfloat16 \
       --mem-fraction-static 0.8 \
       --port 30000

   python scripts/regenerate_train_data.py \
       --model Qwen/Qwen3-4B \
       --reasoning disable \
       --temperature 0 \
       --max-tokens 4096 \
       --concurrency 128 \
       --server-address localhost:30000 \
       --input-file-path ./cache/dataset/perfectblend_train.jsonl \
       --output-file-path ./cache/dataset/perfectblend_qwen3-4b_regen.jsonl
   ```

   Pass several `--server-address` values to regenerate in data parallel. The
   output path is the `--train-data-path` of the training command below.

## 🔥 Training

VAT is enabled by `--loss-type vat` on the DFlash trainer, `scripts/train_dflash.py`.
The target model runs in every trainer process, through Hugging Face
Transformers (`--target-model-backend hf`, the default) or an in-process SGLang
model runner (`--target-model-backend sglang`). The Qwen3-4B example uses the
paper's settings (5-layer DFlash draft, block size 16, 3 epochs) with the HF
target:

```bash
bash examples/run_qwen3_4b_dflash_vat_online.sh 8        # 8 GPUs
```

It runs:

```bash
torchrun --standalone --nproc_per_node 8 scripts/train_dflash.py \
    --target-model-path Qwen/Qwen3-4B \
    --target-model-backend hf \
    --draft-config-path configs/qwen3-4b-dflash.json \
    --train-data-path ./cache/dataset/perfectblend_qwen3-4b_regen.jsonl \
    --on-the-fly-loader \
    --output-dir ./outputs/qwen3-4b-dflash-vat \
    --num-epochs 3 \
    --batch-size 1 \
    --learning-rate 6e-4 \
    --warmup-ratio 0.045 \
    --max-grad-norm 1.0 \
    --max-length 4096 \
    --chat-template qwen \
    --attention-backend flex_attention \
    --block-size 16 \
    --num-anchors 512 \
    --loss-type vat \
    --loss-decay-gamma 7 \
    --vat-kd-weight 1.0 \
    --vat-kd-temperature 2.0 \
    --vat-accept-head-weight 1.0 \
    --vat-self-cov-weight 0.6 \
    --log-interval 50 \
    --save-interval 5000 \
    --report-to tensorboard
```

| Flag | Meaning |
| --- | --- |
| `--loss-type vat` | Use the VAT objective instead of the DFlash loss. |
| `--loss-decay-gamma 7` | DFlash position decay `exp(-(k-1)/gamma)`, re-anchored by VAT at the first rejection `k*` (required). |
| `--vat-kd-weight`, `--vat-kd-temperature` | Soft-label (target distribution) term and its temperature. |
| `--vat-accept-head-weight` | Verification-head loss weight. |
| `--vat-self-cov-weight` | Self-coverage term for an additional gain. On each block with a rejection it adds `(1/R) * sum_{j >= j*} -log max(P_j, floor)`, where `P_j` is the teacher-forced probability of the label prefix up to row `j`, `j*` the first rejected row, `R = block_size - 1`, and `floor` is `--vat-self-cov-floor` (default `1e-6`). Use a weight of about 0.4 to 0.6. |
| `--on-the-fly-loader` | Tokenize each conversation in the DataLoader workers instead of preprocessing the dataset upfront. |

To run the target with SGLang instead, replace `--target-model-backend hf` with
`--target-model-backend sglang --sglang-mem-fraction-static 0.25`. The SGLang
runner reserves that fraction of every GPU (default 0.4); 0.25 leaves room for
training on an 80 GB GPU.

For multiple nodes, run the example on every node with the `torchrun`
rendezvous variables, for example on 8 nodes:

```bash
NNODES=8 NODE_RANK=<0..7> MASTER_ADDR=<node-0 host> MASTER_PORT=29500 \
    bash examples/run_qwen3_4b_dflash_vat_online.sh 8
```

Each checkpoint `outputs/qwen3-4b-dflash-vat/epoch_{e}_step_{s}` is a Hugging
Face draft directory (`config.json`, `model.safetensors`) that loads as a plain
`DFlashDraftModel`. The verification head is training-only: it is kept in
`training_state.pt` for `--resume` and is not part of the draft weights.

`--resume` restores the draft, the accept head, and each rank's optimizer shard
from the latest checkpoint in `--output-dir`; resume with the same number of
GPUs. Training logs `train/vat/{ce_loss, kd_loss, accept_loss, mean_accepted}`
(and `train/vat/self_cov_loss` when it is enabled).

## 💯 Evaluation

VAT does not change drafting or verification at inference, so a trained
draft is evaluated exactly like any DFlash draft. Follow the official
[DFlash evaluation](https://github.com/z-lab/dflash) to measure the average
acceptance length and wall-clock speedup.
